# H2 / MySQL 호환성 위험

## 마이그레이션 분리

- 로컬 H2: 인메모리 내장, Flyway 비활성, Hibernate `ddl-auto=update`
- AWS MySQL: `classpath:db/migration/mysql`
- 테스트: H2 `create-drop`; 마이그레이션 통합 테스트만
  `classpath:db/migration/h2` SQL과 Flyway 활성화

`db/migration/h2`가 SQL 파일인 것은 Flyway가 버전이 붙은 SQL 마이그레이션을
실행하기 때문이다. 이 파일은 일반 로컬 실행의 스키마 생성용이 아니며,
H2 마이그레이션 자체의 유효성을 검증하는 통합 테스트에서만 사용한다.

기존 H2 SQL에는 `GENERATED BY DEFAULT AS IDENTITY`, `UUID`,
`TIMESTAMP WITH TIME ZONE`, `ALTER COLUMN ... DROP NOT NULL` 및 로컬
시드가 포함되어 MySQL에 적용하지 않는다.

## 위험 기록

### 1. 시간대

- 위치: 엔터티의 `LocalDateTime`, `RefreshToken`의 `Instant`
- H2 동작: `TIMESTAMP`와 `TIMESTAMP WITH TIME ZONE`
- MySQL 예상 차이: MySQL 마이그레이션은 `DATETIME(6)` 사용. JVM·JDBC
  시간대 설정에 따라 `Instant` 변환 차이 가능
- EC2 검증: 회원가입 후 갱신 토큰 만료, 재시작 전후 생성 시각,
  아시아/Seoul 경계값 확인
- 상태: 경고

### 2. 불리언

- 위치: 삭제·댓글·토큰 `revoked` 필드
- H2 동작: `BOOLEAN`
- MySQL 예상 차이: `BOOLEAN`은 `TINYINT(1)` 별칭
- EC2 검증: Hibernate `ddl-auto=validate` 성공 및 참/거짓 CRUD
- 상태: 경고

### 3. 정렬 규칙과 고유성

- 위치: 사용자 이메일·닉네임, 본문과 한글/이모지
- H2 동작: H2 기본 비교 규칙
- MySQL 예상 차이: `utf8mb4_0900_ai_ci`는 대소문자·악센트 비구분
- EC2 검증: 대소문자만 다른 이메일/닉네임과 한글·이모지 입력
- 상태: 경고

### 4. 페이지네이션과 NULL 정렬

- 위치: 게시글·북마크 슬라이스/정렬 저장소
- H2 동작: H2 정렬 규칙
- MySQL 예상 차이: 동률과 NULL 순서가 다를 수 있음
- EC2 검증: 같은 `created_at` 데이터로 다음 페이지 중복·누락 확인
- 상태: 경고

### 5. 스키마 검증

- 위치: `application-aws.yaml`
- H2 동작: 테스트는 `create-drop`, 로컬은 Hibernate `update`와 Flyway 비활성
- MySQL 예상 차이: 엔터티와 MySQL 타입이 일치하지 않으면 시작 실패
- EC2 검증: 첫 시작에서 Flyway 성공 후 Hibernate 검증 로그 확인
- 상태: AWS 검증 전 경고

## 금지

- H2 테스트 성공만으로 MySQL 호환 통과 판정 금지
- 적용된 Flyway 마이그레이션 수정 금지
- 운영 DB에 H2 로컬 시드 적용 금지
- Hibernate `ddl-auto=update/create` 사용 금지
